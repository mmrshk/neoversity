# Завдання 5 — порівняння алгоритмів пошуку підрядка

## Задача

Порівняти ефективність трьох класичних алгоритмів пошуку підрядка —
**Боєра-Мура** (`boyer_moore.py`), **Кнута-Морріса-Пратта** (`kmp.py`) та
**Рабіна-Карпа** (`rabin_karp.py`) — на двох реальних текстах
(`стаття 1.txt`, `стаття 2.txt`).

Час виконання вимірюється модулем `timeit` для двох видів підрядків:

- такого, що **дійсно існує** в тексті;
- **вигаданого** підрядка, якого в тексті немає (найгірший сценарій — алгоритм
  змушений пройти весь текст).

На основі отриманих даних визначається найшвидший алгоритм для кожного тексту
окремо та в цілому.

## Як запустити

```bash
cd goit-algo-hw-05
python3 benchmark.py
```

Скрипт сам читає обидва файли (у кодуванні `utf-8`), перевіряє коректність
реалізацій (порівнює з `str.find`) та виводить таблицю результатів.

## Обрані підрядки

| Текст      | Існуючий підрядок            | Вигаданий підрядок                  |
|------------|------------------------------|-------------------------------------|
| Стаття 1   | `алгоритм`                   | `квантовий нейроінтерфейс_xyz123`   |
| Стаття 2   | `рекомендаційної системи`    | `квантовий нейроінтерфейс_xyz123`   |

## Теоретичні оцінки складності

| Алгоритм         | Передобробка | Найкращий випадок | Середній випадок | Найгірший випадок |
|------------------|--------------|-------------------|------------------|-------------------|
| Boyer-Moore      | \(O(m + \sigma)\) | \(O(n / m)\)  | сублінійний      | \(O(n \cdot m)\)  |
| KMP              | \(O(m)\)     | \(O(n)\)          | \(O(n)\)         | \(O(n)\)          |
| Rabin-Karp       | \(O(m)\)     | \(O(n + m)\)      | \(O(n + m)\)     | \(O(n \cdot m)\) (колізії хешу) |

де \(n\) — довжина тексту, \(m\) — довжина шаблону, \(\sigma\) — розмір алфавіту.

## Висновки

1. **Найшвидший алгоритм для Статті 1 — Boyer-Moore.**
2. **Найшвидший алгоритм для Статті 2 — Boyer-Moore.**
3. **У цілому по обох текстах найшвидшим теж є Boyer-Moore.**

Чому Boyer-Moore вигравав у всіх сценаріях:

- **Сублінійна поведінка на природній мові.** Завдяки таблиці зсувів за
  «поганим символом» (bad-character rule) алгоритм пропускає одразу до
  \(m\) символів тексту, коли натрапляє на символ, відсутній у шаблоні. На
  українському тексті з великим алфавітом більшість порівнянь обриваються
  миттєво, і ефективна швидкодія близька до \(O(n / m)\).
- **KMP** має чесний \(O(n + m)\), але переглядає **кожен** символ тексту
  щонайменше один раз — на природній мові це значно більше роботи, ніж у
  Boyer-Moore.
- **Rabin-Karp** виявився найповільнішим, бо чиста Python-реалізація
  поліноміального хешу на кожному кроці виконує дві арифметичні операції з
  `pow`/`%`/`ord`, що інтерпретатор Python робить набагато повільніше за
  прості порівняння символів. Крім того, малий модуль (`101`) спричиняє
  колізії хешу, через що інколи доводиться додатково порівнювати підрядки
  посимвольно.

Окремо помітно, що **різниця між алгоритмами найбільш виражена на
вигаданому підрядку** — там, де доводиться сканувати весь текст. На
існуючому підрядку, що знаходиться відносно близько до початку тексту, всі
три алгоритми працюють настільки швидко, що різниця хоч і зберігається у
порядку величини, але абсолютний час дуже малий (мікросекунди).

**Підсумок:** для пошуку підрядків у природномовних текстах на Python
найкраще себе показує алгоритм Боєра-Мура; KMP — стабільний другий варіант
із гарантованою лінійною складністю; Rabin-Karp у такій реалізації
доцільно використовувати лише там, де потрібен пошук багатьох шаблонів
одночасно (його справжня перевага), а не для пошуку єдиного підрядка.
